## `study`

Create a study directory, register phase artifacts, or show a study's status.

A study: one directory holding every phase of one ReaxFF force field's
development, marked by `study.json`.

`study.json` records the goal and a registry of the artifacts each phase
produced (`trainset`, `params_spec`, `fit`, `ffield`, `md_check`, ...), so
later phases, the usage accounting and the final report find them without
guessing paths. Standard layout, which `--init` creates:

    <study>/study.json  STUDY.md  journal.jsonl
    01_data/       reference structures and their DFT labels
    02_trainset/   trainset.yaml / validset.yaml (+ the packed extxyz)
    03_fit/        params.yaml, sensitivity, one directory per fit
    04_validate/   evaluate / md-check / scans of candidate ffields
    05_refine/     iterative refinement rounds (MD -> select -> label -> refit)
    06_deploy/     the delivered ffield + its card
    usage/

Stages that write inside a study (any `--output-dir` below a `study.json`)
add their login-node CPU time to `usage/local.jsonl` automatically (see
cli.py); Slurm jobs are found by `usage` through sacct's working directory.

## `usage`

CPU-hours used by a study (Slurm via sacct + login-node ledger), by phase and job.

CPU-hours spent on a study, by phase and by job.

Slurm jobs come from `sacct`, filtered by working directory: every job
whose WorkDir is inside the study (or one of its `extra_roots`) counts,

## `ffield-info`

Summarize a ffield: elements, sections, missing interactions for a chemistry, sanity checks, parameter ids, diff.

Inspect a ReaxFF force field: what it contains, what it lacks for a
chemistry, which parameter ids exist, sanity checks, and differences
between two files.

Checks reported (none modify the file):

- interactions missing for the requested elements: bonds, off-diagonal
  pairs, angles, torsions (a missing bond means no covalent bonding between
  those elements; a missing angle or torsion contributes no energy)
- EEM parameters below the polarization-catastrophe bound eta >= 7.2 gamma
  (SCM ReaxFF manual), which lets charges run away at short distance
- elements with neither vdW shielding (gamma_w > 0.5) nor an inner wall
  (rcore2, acore2 > 0.01): LAMMPS warns about these; nothing keeps such
  atoms apart at very short range except the bond terms
- the bond-order cutoff (general parameter 30 / 100), which with LAMMPS'
  thb_cutoff controls where interactions switch off discontinuously
  (Furman & Wales 2019 [FW19])

| input | type | default | description |
|---|---|---|---|
| `ffield` | string |  |  **(required)** |
| `elements` | array / null |  | Check coverage for this chemistry (default: every element in the file). |
| `list_params` | string / null |  | Regex over parameter ids to list with values (e.g. 'bond:C-H:.*' or 'atom:Si:.*'). |
| `diff` | string / null |  | Another ffield: report every parameter that differs. |
| `diff_tol` | number | 1e-06 |  |

## `ffield-library`

Index a directory of published ffields: per-parameter value ranges (for bounds) and element donors.

Index a library of published force fields: parameter ranges for bounds,
element donors for new elements.

Shchygol et al. bounded each parameter by an interval and built "educated"
starting guesses from the median of historical values of the same parameter
(same elements first, then any elements) [Sh19]; Dumortier et al. used the
historical range widened to include ±20% around the start [Du24]; Larsson
et al. found the choice of ranges mattered more than any optimizer setting
[L13]. This stage produces those statistics from whatever ffields you have:

    library.json
      params:   "bond:C-H:De_s"  -> {min, max, median, n, sources}
                "*:bond:De_s"    -> same, over every element combination
      elements: "Si" -> [files defining Si, with their header lines]

`params-select --bounds library --library library.json` uses it. Element
keys are order-normalized, so C-H and H-C pool together. Files that fail to
parse are listed, not fatal. `setup --component ffield_library` fetches the
ReaxFF files distributed with LAMMPS into deps/ffields/ as a starting set;
add your group's ffields with --dirs.

| input | type | default | description |
|---|---|---|---|
| `dirs` | array / null |  | Directories (searched recursively) and/or ffield files. Default: deps/ffields. |
| `pattern` | string | "*ffield*" | Glob for files inside directories. |

## `ffield-merge`

Build a starting ffield for a chemistry from a base ffield + element donors + analog seeding; reports what needs fitting.

Assemble a starting force field for a new chemistry from published ones.

ReaxFF parameter sets are not freely combinable: they come in "branches"
(e.g. the combustion branch built on Chenoweth 2008 and the aqueous branch,
which re-fits O/H to get liquid water right), and within one branch only the
bond and angle terms between newly combined elements need fitting, while
crossing branches needs much more refitting [S16]. So:

  1. `--base` supplies the general parameters and its elements (keep the
     elements you need with --elements);
  2. each `--add EL=donor.ffield` copies element EL's atom block and every
     interaction among the final elements that the base lacks;
  3. `--analog NEW=OLD` fills interactions still missing for NEW by copying
     the corresponding OLD ones (e.g. Si=C gives Si-H from C-H), the usual
     way to seed a new element before fitting (cf. the ParAMS ZnS example,
     which seeds S blocks from O [P21]);
  4. everything copied across files or from analogs is listed in
     `needs_fitting`, which `params-select --from-merge` can activate.

The report says which general parameters differ between base and donors:
many differences mean the donor is from another branch and its blocks were
fitted against different general parameters.

| input | type | default | description |
|---|---|---|---|
| `base` | string |  | Base ffield (its general parameters are kept). **(required)** |
| `elements` | array / null |  | Final element list (default: base elements + added ones). |
| `add` | array / null |  | EL=donor_ffield entries. |
| `analog` | array / null |  | NEW=OLD entries: seed missing NEW interactions from OLD ones. |
| `header` | string / null |  |  |

## `data-generate`

Generate reference geometries: molecules, bond/angle/torsion scans, dimers, EOS, rattled and MD frames (one packed extxyz).

Generate unlabeled reference geometries for a ReaxFF training set.

One packed `structures.extxyz` comes out (frames named, grouped and tagged
with how ReaxFF and the DFT labeler should treat them: single point, or
relaxation holding a restrained coordinate). Labels come next from `label`.

Typical recipe (--json-in):

```json
{"molecules": ["CH4", "C2H6", "C2H4", "H2O", "CH3OH", "smiles:CC(=O)O"],
 "scans": ["bond", "angle", "torsion"],
 "dimers": true,
 "crystals": ["C:diamond:3.567"],
 "rattle": {"n": 4, "sigma": 0.08},
 "trajectories": [{"path": "md/dump.extxyz", "stride": 20}]}
```

What to include, and why, is in the `reaxff-training-set` skill: every
bond type needs a dissociation curve, every angle type a bending scan,
condensed phases an equation of state, and forces on distorted frames make
the fit far better determined than energies alone.

## `label`

Label structures with DFT (Quantum ESPRESSO via Slurm), GFN-xTB (local) or a reference ReaxFF ffield.

Label reference structures with energies, forces, stresses and charges.

Backends (the level of theory is recorded on every frame as `lot`, and
`trainset-build` refuses to mix levels — one level of theory per fit):

  qe      Quantum ESPRESSO DFT, the production backend. Prepares one
          directory per frame (pw.in [+ projwfc.in]), submits ONE Slurm job
          (or a chain of 1 h chunks) that runs frames in parallel lanes and
          resumes cleanly, then `--collect` parses the finished frames.
          Restrained scan frames are relaxed under the matching QE
          constraint; stretched bonds get broken-symmetry spin (see
          labeling/qe.py).
  xtb     GFN2-xTB / GFN1-xTB through tblite, locally in parallel: minutes
          instead of node-hours, for designing and debugging a training set
          before paying for DFT. Not a substitute for DFT labels. Frames
          whose SCF fails are retried with 3000 K electronic temperature
          (open-shell / stretched cases); periodic boxes are slow.
  ffield  an existing ReaxFF force field (LAMMPS): for recovery tests
          (perturb a published ffield, refit to its own labels) and for
          fitting a reduced force field to a reference ReaxFF.

Relaxation frames (mode relax / relax_cell) come back with the relaxed
geometry, so geometry items compare relaxed with relaxed.

## `trainset-build`

Build trainset.yaml (+ validset.yaml) from labeled structures: relative energies, forces, geometries, charges, lattice, reactions.

Turn labeled structures into a weighted training set (and a held-out
validation set).

Item rules (each can be tuned or switched off in the recipe):

  energy     Only differences: within every group of same-composition
             frames (a scan, an EOS, an MD batch), E_i - E_ref with ref the
             group's lowest-energy frame. ReaxFF and DFT absolute energies
             are not comparable; relative energies are what ReaxFF training
             sets have always used [vD01, C08]. EOS groups are per atom.
  reactions  explicit balanced combinations: [[name, coeff], ...]
  forces     per-frame force sets on chosen kinds (default: rattle, md,
             eos). Not on relaxed scans (their forces are ~0 by
             construction) and not on dimer curves, whose short-range
             forces (thousands of kcal/mol/Å at 0.6 Å) would swamp the loss
             while the energies already carry that information.
  geometry   bond lengths and angles of DFT-relaxed molecules (mode relax,
             kind molecule), compared after ReaxFF relaxation
  charges    reference charges where the labels have them (loosely
             weighted: population schemes disagree, and charges alone
             cannot pin EEM parameters [V11])
  lattice    a, b, c (and volume) of relaxed crystals (mode relax_cell)

Sigmas default to ParAMS-like accepted errors [P21] (energy 2 kcal/mol,
forces 5 kcal/mol/Å, distance 0.02 Å, angle 2°, charge 0.1 e, lattice
0.05 Å). `high_energy_scale` (default 50 kcal/mol) loosens sigma for frames
far above their group minimum, sigma·(1 + ΔE/scale): a frame 1000 kcal/mol
up a repulsive wall still counts, but cannot dominate the fit. ReaxFF cannot
follow DFT into every high-energy corner and should not trade the
low-energy region for it (a heuristic, cf. ParAMS' Gaussian weighting of
PES scans; a handful of items dominating the loss is the failure mode
Shchygol et al. traced their noise to [Sh19]). Set it to 0 to disable.

Validation split (`validation_fraction`, by whole group by default so a
scan is never half in each set) gives the held-out set for early stopping
and for choosing among near-equal fits [Sh19, P21].

One level of theory: frames whose `lot` differs are refused unless
`allow_mixed_lot` (don't).

|---|---|---|---|
| `structures` | array / null |  | Labeled extxyz file(s). |
| `energy_sigma` | number | 2.0 |  |
| `eos_sigma_per_atom` | number | 0.5 |  |
| `high_energy_scale` | number / null | 50.0 | kcal/mol; sigma grows as 1 + ΔE/scale above the group minimum (0 = off). |
| `max_relative_energy` | number / null |  | Drop energy items more than this (kcal/mol, per atom for EOS x natoms) above the group minimum. |
| `forces_kinds` | array / null |  | Kinds that get force items (default rattle, md, eos). |
| `forces_sigma` | number | 5.0 |  |
| `forces_weight` | number | 1.0 |  |
| `forces_every` | integer | 1 | Use every n-th eligible frame for forces. |
| `geometry` | boolean | true |  |
| `distance_sigma` | number | 0.02 |  |
| `angle_sigma` | number | 2.0 |  |
| `charges` | boolean | true |  |
| `charges_sigma` | number | 0.1 |  |

## `params-select`

Select active ffield parameters (presets per fitting stage, element filters, data coverage) with literature-based bounds and constraints.

Choose which parameters a fit may change, and their bounds.

The single most consequential choice in ReaxFF fitting [L13]. Defaults
follow the literature:

  * fit in stages, not everything at once: charges -> bonds -> valence
    angles -> torsions -> vdW / coordination -> joint refinement ([vD01,
    C08, S16]; presets below), and no more than ~sqrt(n_items) parameters
    at a time (ParAMS rule of thumb [P21]);
  * activate only parameters the training data can see: multi-body terms
    whose elements never occur together in a training structure are left
    out (`--require-data`, default on), as ParAMS' ZnS example freezes
    "anything without training data" [P21];
  * when extending a force field, touch only the new element's terms
    (`--elements Si`), keeping published blocks intact for compatibility
    with the rest of the branch [S16, Sh19];
  * never optimize structural switches, valencies, masses, unused slots,
    taper radii or the bond-order cutoff; keep zero-valued (switched-off)
    terms at zero unless `include_zero`;
  * bounds: ±20% of the start value by default (ParAMS bounds_scale 1.2
    [P21]); `--bounds library` uses the range of published values from
    `ffield-library` (Shchygol's historical intervals [Sh19]); `union`
    takes the wider. Hard physical limits (positive energies/radii,
    exponents >= 1, 0 <= theta_00 <= 180) always apply;
  * default constraints: r_s >= r_pi >= r_pipi [P21] and, for EEM
    parameters, eta >= 7.2 gamma (polarization-catastrophe bound).

`--from-sensitivity sensitivity.json --top N` keeps the N most influential
parameters (ParAMS' sensitivity-first workflow, Freitas Gustavo 2023 [FH23]).
`--from-merge merge_report.json` activates the interactions ffield-merge
copied from donors/analogs.

|---|---|---|---|

| `trainset` | string / null |  | Used for --require-data and the sqrt(n) check. |

## `sensitivity`

Rank active parameters by how much the training-set loss depends on them (one-at-a-time or HSIC).

Which parameters does the training set actually constrain?

Fitting parameters the data cannot see adds noise and overfitting, not
accuracy; Freitas Gustavo, Hellström and Verstraelen showed that optimizing
a small, sensitive subset converges faster to comparable loss with less
overfitting [FH23], and ParAMS' disulfide refit first scanned all 701
parameters one at a time and kept the 35 most sensitive [P21].

Methods:
  oat    one-at-a-time: each parameter moved ±delta (fraction of its
         range) from the start, everything else fixed: 2n+1 evaluations.
         Local, cheap, and it flags "fragile" parameters whose small
         changes break structures (NaN, QEq failure).
  hsic   global: `samples` uniform random points in the box, sensitivity of
         log(loss) to each parameter by the Hilbert-Schmidt independence
         criterion (the ParAMS/[FH23] measure), normalized to sum 1.

Output `sensitivity.json` (ranking with per-group loss changes for oat),
consumed by `params-select --from-sensitivity --top N`.

## `fit`

Fit active ReaxFF parameters (CMA-ES default; multi-start with pruning, validation-based choice, resumable, Slurm-ready).

Optimize ReaxFF parameters against a training set.

The protocol follows what the optimizer benchmarks found, not one long run:

  1. `restarts` independent runs, each for `short_evals` evaluations. Run 0
     starts from the given force field; the others from random points in
     the central half of every range (Shchygol's "random guess": the best
     of their 150 runs always came from one [Sh19]).
  2. Only the `keep` best runs continue to `max_evals` ("run many short
     CMA-ES runs and continue only the best" [Sh19]; GloMPO automates the
     same idea [GW22]).
  3. The result is the run with the lowest *validation* loss when a
     validation set is given (near-degenerate minima are common, and the
     held-out set is how to choose among them [Sh19, P21]), else training.
  4. Optional local polish of the winner (SOPPE or Nelder-Mead).

Every run keeps its best ffield; together they are the committee whose
disagreement `refine-select` uses to pick new training data ("add data
where near-optimal solutions disagree" [Sh19]).

Outputs: fit.json (all runs, the choice and why), best.ffield,
best_report.json (errors per kind/group, train and validation), and
runs/run_XX/{history.jsonl, best.ffield, best_val.ffield, checkpoint.pkl}.
Interrupted fits (time limit, a 1 h queue) resume with `--continue`;
`--machine` submits the whole thing as a chain of Slurm jobs that do so.

## `evaluate`

Errors of one or more ffields on training/validation/test sets, scan curves, parity plots, diatomic short-range and smoothness checks.

Evaluate force fields on training / validation / test sets, side by side.

For each ffield and each set: loss, per-kind and per-group RMSE/MAE/max
error in natural units, failed structures; per-item predictions
(items.csv); scan curves (curves.json: reference vs every ffield along each
bond/angle/torsion/dimer/EOS group); optional parity and scan plots.

`--pair-check` adds a fine diatomic scan of every element pair with every
ffield (no reference data needed), reporting for each pair:

  * short-range repulsion: does the energy keep rising as the atoms are
    pushed together down to `pair_rmin` (and how high is it there)? A force
    field whose diatomic curve turns over at short range lets atoms collapse
    at high temperature or in collisions (too-soft short-range repulsion is documented for ReaxFF in
    energetic deposition, Caro 2020 [Ca20]); inner-wall parameters
    (rcore2/ecore2/acore2) or vdW shielding fix it;
  * discontinuities: jumps in energy or force along the curve, which come
    from ReaxFF's hard bond-order cutoffs and cause NVE energy drift and
    noisy geometry optimizations (Furman & Wales 2019 [FW19]).

Compare a fitted ffield with its starting point and, where one exists, the
published force field for the same chemistry: improvement must show on the
validation and test sets, not only on training.

## `md-check`

MD stability of ffields: NVT->NVE runs per system and temperature; drift, Furman-Wales ratio, close contacts, charges, species.

MD validation of candidate force fields: do they survive dynamics?

A low training loss says nothing about stability: well-fitting ReaxFF
parameter sets can fail to keep a crystal stable at 2000 K (Nakata & Bai
[NB19]), and overfitting shows up as "low training error but unphysical MD"
[Sh19]. For every (ffield, system, temperature) this runs, in LAMMPS,

    velocity -> NVT (Nose-Hoover) for `nvt_ps` -> NVE for `nve_ps`

and reports:

  completed        no LAMMPS error, NaN or lost atoms
  nve_drift        total-energy drift (kcal/mol/ps per atom) in the NVE part
  nve_ratio        sqrt(<dE_tot^2>/<dE_kin^2>): Furman & Wales call < 10%
                   acceptable; ReaxFF's hard bond-order cutoffs push it up
                   (69-152% for published force fields in their tests) [FW19]
  min_distance     closest approach per element pair over the trajectory;
                   flagged below `contact_factor` x (sum of covalent radii):
                   atoms collapsing onto each other
  max_abs_charge   largest |q|; flagged above `max_charge` (charge runaway /
                   polarization catastrophe)
  species          molecules in the final frame (covalent connectivity), to
                   compare with what the chemistry should do

Systems: any periodic or molecular structures (e.g. `data-generate
--boxes`). Trajectories are written as one extxyz per run (frames every
`dump_every` steps) for `refine-select`. Many runs execute in parallel, one
LAMMPS process each; `--machine` runs the whole set on a compute node.

## `refine-select`

Select MD frames for DFT labeling by committee disagreement and short-contact extrapolation (one refinement round).

Pick new training frames from MD: where the force field is uncertain or
extrapolating.

One refinement round is: md-check (trajectories with the current fit) ->
refine-select -> label -> trainset-build --merge-into -> fit -> md-check.
It is the standard way to make a fit hold up in the dynamics it will be
used for (training on MD-sampled DFT frames: De Angelis 2024 [DA24],
Dumortier 2024 [Du24]; the same loop with DFT relabeling of ReaxFF-MD
frames seeds Yoo et al.'s CHNO network [Yo21]). No published ReaxFF work
runs it with an uncertainty-driven selection, so the selection rules here
are this toolkit's, built on two literature observations:

  committee  independent fits reach near-equal loss with different
             parameters [L13, Sh19]; where they disagree the data does not
             constrain the force field, and Shchygol et al. recommend adding
             training data exactly there [Sh19]. Disagreement = spread of
             energy per atom and of forces across the committee (the
             `committee` list in fit.json).
  contacts   frames with a pair distance shorter than anything the training
             set contains are extrapolations in the region where ReaxFF most
             often fails (collapse, missing repulsion).

Frames are scored, then picked greedily with diversity (no two frames
closer than `min_gap` in the same trajectory) up to `n_select`.

|---|---|---|---|
| `committee` | array |  | ffields of independent fits (fit.json 'committee'), >= 2. **(required)** |
| `trajectories` | array |  | extxyz trajectories (md-check traj.extxyz) or frame sets. **(required)** |
| `trainset` | string / null |  | Current training set: its shortest pair distances define 'extrapolating'. |
| `n_select` | integer | 40 |  |
| `stride` | integer | 1 |  |
| `min_gap` | integer | 3 | Minimum frame separation within one trajectory. |
| `contact_weight` | number | 1.0 |  |
| `round` | integer | 1 |  |
| `workers` | integer / null |  |  |
| `charge_method` | string | "qeq" |  |

## `job-status`

Verdict on a submitted job: queued/running/succeeded/failed (why, and the fix)/completed-without-results.

One verdict for a submitted job: is it done, did it work, and if not, why.

Reads the `job.json` every submission writes into its work directory (job
id, expected result files) and combines it with the scheduler's view.

- **State**: `squeue` while queued or running; otherwise `sacct`, with
  state, exit code, elapsed time and limit.
- **Expected results**: each must exist and, for JSON, parse.
- **Logs**: the tail of `stdoutmsg` and any `*.out` in the directory.

Verdicts:

| verdict | meaning |
|---|---|
| `QUEUED` / `RUNNING` | still in the scheduler |
| `SUCCEEDED` | finished, and every expected result exists and parses |
| `COMPLETED_WITHOUT_RESULTS` | Slurm says COMPLETED but results are missing: a non-shared job directory (/tmp), or an error the job script swallowed |
| `FAILED` | TIMEOUT, OUT_OF_MEMORY, NODE_FAIL, CANCELLED or a nonzero exit; `reason` and `fix` say what to do |
| `UNKNOWN` | the scheduler no longer knows the job (accounting purged) and results are missing |

Read-only: it never resubmits or cancels anything.
